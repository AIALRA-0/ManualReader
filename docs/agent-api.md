# 1 用户怎样把当前项目交给 Codex

用户点击网页上的连接按钮，把生成的说明复制到自己的 Codex 对话；网页不创建对话、不自动调用回答模型

本地连接使用页面提供的 PIN，远程连接使用短期配对码换取项目令牌；不要把连接码、令牌或原始任务日志写到公开 Issue

读取当前接口的 `/api/guide`，远程对应 `/machine/v1/guide`，以实际返回的字段、权限和 `client_files` 为准

# 2 怎样读取与写入

本地请求带 `X-Reader-Pin` 和 `X-Reader-Material`；远程请求带 `Authorization: Bearer …`，项目必须与令牌授权的项目相同

下面列出本地接口，远程把 `/api` 换成 `/machine/v1`

- `GET /api/content` 读取文件、讲解与展示关系
- `GET /api/learning` 读取独立学习目录和当前章节
- `GET /api/work` 汇总当前项目已保存且未回答的问题，以及必要原句和已登记术语
- `POST /api/runs` 准备独立任务组，客户端按当前配置并行处理并逐组保存输出
- `POST /api/translations` 按原编号写入译文
- `POST /api/content/files` 上传原件或实际生成的图片
- `POST /api/content/explanations` 写入章节讲解与来源关联
- `POST /api/rounds/{round_id}/result` 保存回答、术语和练习
- `POST /api/teaching/result` 保存当前学习章节的讲解、术语和练习
- `POST /api/focus` 定位原文与译文，不代替用户标记已读

例如，对已有文件写入一个已知原段落的译文

```json
{
  "file_id": "primary",
  "complete": false,
  "translations": [
    {
      "source_id": "demo-p1",
      "text": "缓存保存最近使用过的结果，命中时直接复用已有值"
    }
  ]
}
```

`source_id` 必须来自实际读取的项目，不根据正文顺序猜编号；句级字段按当前接口返回的翻译任务提交，不用整段文字覆盖已有句子映射

# 3 一轮回答怎样结束

下载 `client_files` 中列出的当前客户端和规则模块到同一目录，使用已登录的 Codex；连接凭据不放到模型提示词里。用户选择记住连接时，客户端将项目凭据交给操作系统凭据库保存，重建进程后按网站和项目恢复；用户撤销授权后，已保存的凭据也不能继续访问

默认执行器使用 `gpt-6.1-terra`、`high`、普通服务；当前执行器最多并行四组，实际组数以任务和配置为准。每组输入只包含问题、去重原句、所需概念和必要上下文，不重复加载全部对话历史；这里只说明当前实现，没有新增模型速度或费用承诺

复杂回答在同一次调用中先组织少量教学步骤，再写最终回答；不增加审稿 Agent，不用循环修复扩大开销

写回内容需要遵守以下规则

- 回答先写 `原文：`，空行后放实际来源，再写 `回答：`，空行后开始解释
- 讲解必需的新概念先用普通话和具体操作说明，再引入名称；术语登记不代表用户已经理解
- 术语提交名称、定义、直观解释和关联问题；已有概念复用真实 ID，新概念不猜 ID
- 选择题围绕实际内容生成，不能靠最长选项或固定答案位置提示正确答案
- 用户显式要求看图时，读取提供的原图并在回答中引用真实地址；新图片实际生成后上传文件，再使用返回的地址
- 写回后继续处理当前章节的问题，只有用户勾选完成才进入下一节

原文文件、译文、讲解和追问各有稳定编号，不能为了显示方便把问题重新挂到另一段；术语与练习按轮累加，已有笔记不清空

# 4 新插图怎样进入回答

同一次写作决定是否需要图，普通词义和简单算式不强行配图。优先引用 `sources.media_items` 的真实地址，分支过程可直接输出 Mermaid；需要位图时使用实际图像生成工具

默认执行器启用 `image_generation`，`generated_assets` 返回 `path`、`alt`、`question_ids`。客户端只接受本组目录或当前会话 `generated_images` 目录中的实际文件，去掉元数据后上传，并把返回地址插入关联回答；其他会话和任意磁盘文件不能借此上传。没有工具时可保留 `visual_requests`，由当前用户手动触发的 Codex 接续执行，不伪造地址

图像工具的次数和耗时单独记录，工具没有返回费用时留空，不写成零费用。术语必须有中文全称和英文全称，缺失名称由现有的一次集中补齐处理，不增加逐题审稿循环

错题本的浏览器接口为 `GET /api/practice-book` 和 `POST /api/practice-book`，支持开始复习、作答、添加、编辑和确认移除。复习记录与原始练习分开保存；机器配对令牌不会因此取得修改用户作答或进度的权限

# 5 Agent 怎样安全删除问题或回答

先确认用户任务确实要求删除，再读取预览；不能因为问题不在当前页面就判断它应该删除。远程路径将下例中的 `/api` 换成 `/machine/v1`

1. 调用 `POST /api/questions/{question_id}/deletion-preview`，提交 `{"target":"question"}`；只删回答时改为 `{"target":"answer"}`
2. 读取返回的问题原话、版本和受影响追问编号，实际核对当前项目与用户任务；删除问题会连同其追问一起隐藏
3. 核对无误后调用 `POST /api/questions/{question_id}/deletion-confirm`

```json
{
  "confirmation_id": "从本次预览读取",
  "expected_version": 2,
  "expected_text": "从本次预览读取的问题原话",
  "confirmed": true
}
```

确认只对同一项目、调用者、问题及预览内容有效，五分钟后失效，成功后不能重用；服务重启也会使未确认预览失效。原问题、回答或受影响追问有变化时，需要重新读取并核对。旧接口仅传 `confirmed:true` 不能绕过机器删除确认，自动保存空列表也不能代替删除

删除保留历史、笔记、练习和手动进度。删掉回答或编辑问题后，默认 `/work` 和 `/runs` 使用同一套当前回答与问题版本判断；旧片段、旧回答时间或删除标记不会让当前问题漏出待答池。用户明确要求重答已答问题时，按 `/guide` 提供的原编号重答入口准备单题，不要把全部已答题一起重跑

浏览器回答阅读状态由实际展开触发，新回答或修改后的回答先显示黄色，展开后变绿；机器写作不代替用户登记已读


# 7 写作期间网页换章怎么办

开始本节写作时读取 `GET /api/work?mode=lesson`，保留返回的 `lesson_task_id`；`POST /api/teaching/result` 同时传这个编号与原 `learning_node_id`，稿件始终写回任务开始时的章节，网页可以继续停在用户新选的位置

任务在服务端持久保存；服务重启后仍可使用同一项目令牌恢复；同一请求重交通常返回原回执，避免重复追加；另一连接不能冒用任务，未完成的后续章节也不能随意套用任务编号

`409 lesson_selection_changed` 表示页面章节与旧稿不一致，已有稿件留在客户端；有任务时直接重交，没有任务时先回到原章节取得任务后提交原稿；不重新生成，不把它当成配对失效；`401` 和项目权限 `403` 仍按授权错误处理

网页切章提交 `expected_selection_revision`，过时请求返回 `409 selection_changed`，不能覆盖较新的章节；首次读取和 Agent 接手规则都能在当前 `/api/guide` 中取得

# 8 怎样排除网页附属内容

原文完整保存，学习范围单独登记；登录、导航、评论与页尾等不需要学习的单元，通过 `POST /learning/exclusions` 提交 `passage_ids`、`reason` 和可选的 `expected_revision`；恢复时使用 `action: "restore"`；`GET /learning/exclusions` 返回现有登记；本地接口加 `/api` 前缀

排除只改变学习目录与学习覆盖率，不删除原件、问题、笔记或已读状态；同一内容再次载入时继续排除，原件发生变化则原排除失效，需要重新核对；未覆盖内容和已排除内容分别计数，不把排除写成已读或已讲解

# 9 怎样逐章规划和讲解

新项目的 Agent 目录默认采用 `planning_mode: "chapterwise"`；一次请求只能新增一个首层大章节，可同时规划它下面的多个子节；当前章节未由用户手动勾选完成时，不追加下一大章节；现有完整目录继续保留，不自动删章或重新生成

未规划内容登记在 `coverage_plan.deferred`，保留真实覆盖率；当前任务只生成当前章节正文，沿用同一次写作返回译文、讲解、术语和练习的流程；用户手动完成后再进入下一节，不另加确认步骤


# 10 怎样只调整重复标题

`POST /content/explanations/format` 接收 `explanation_id`、`expected_version` 与 `headings: [{block_id, reading_heading}]`；本地接口加 `/api` 前缀；传空字符串明确清除额外标题，后续省略该字段不会被旧排版文件补回；接口只改标题元数据，正文、原编号和历史保留

`GET /guide` 与设置页返回当前写作规则；缺少用户需要的外部事实时主动联网查证，回答与讲解共用同一规则；客户端等待现有写作者真实完成后结算，同一运行目录不能再次派发，已完成回答逐组落盘

讲解与回答中的项目文件链接使用 `[查看文件](/api/project-files/raw?path=examples/example.py)`；先用项目文件接口保存文件，再引用根目录内的相对路径，特殊字符按 URL 编码。阅读器在原文栏打开文件标签，不切换章节或改变主原文映射；外部引用继续使用真实 HTTPS 地址。`GET /guide` 的 `project_files.writing_links` 与写作接口共用这条规则
