# 1 导入后谁负责做什么

阅读器在导入时运行脚本解析，保存原件、目录、内容单元和稳定编号，不自动调用模型。译文和讲解仍由用户在 Codex 对话中触发，Agent 按原编号写回；非中文正文没有成品译文时，译文区留空，不拿原文充当译文

# 2 不同材料怎样保留结构

| 材料 | 脚本会做什么 | 定位与限制 |
|---|---|---|
| PDF | 保存原页、提取文本与版面框，识别标题、图片和图注 | 保留页号与坐标；标题是启发式结果，扫描页不能靠文本提取得到完整正文，需要补充识别或由 Agent 处理 |
| Word DOCX | 按文档顺序读取标题、段落、加粗、斜体、表格、图片和公式文字 | 关联文档单元；不保证复杂浮动版式与 Word 像素一致 |
| PPTX | 按页登记标题、文字框、表格、图片与其他图形，生成页预览 | 保留页号和形状坐标；复杂效果受预览渲染器能力限制 |
| Markdown、文本 | 保留标题、段落、列表、代码、公式和可读取图片 | 代码与公式整体保护，普通换行生成可提问片段 |
| HTML、网页网址 | 保存抓取内容，清理导航等非正文元素，提取标题、段落和图片 | 保留来源网址；普通抓取无正文时尝试浏览器快照，登录或反爬限制仍可能需要用户提供原件 |
| 仓库链接、ZIP、文件夹 | 保存文件树，逐文件解析文档与代码，登记路径和来源单元 | 不执行代码；忽略依赖和版本管理目录，无法解析的文件单独记录，不冒充已经处理完成 |
| 图片 | 保存图片并登记可引用的对象 | 图片名和对象编号可定位；不把未执行的 OCR 当作已识别文字 |
| 空项目 | 先建立项目，等待用户或 Agent 上传原件、译文或讲解 | Agent 可以按学习目录写入讲解，原件以后补入仍使用明确关联 |

# 3 解析或翻译出错后怎样处理

目录和句级关联由数据结构记录，Agent 可以通过接口调整目录、补充文件和按原编号修正译文，不需要重建项目。原件保留，问答和笔记不因重新显示而删除

覆盖率统计检查已登记单元是否有归属、是否有译文以及是否关联讲解，不能证明 PDF 中的每一个像素都被正确理解，也不能把“编号全覆盖”当作译文语义无误

# 4 怎样显示术语

原文、译文、讲解、问题与回答、术语与练习分别设置。每栏标题右侧的标签图标打开七种命名模式，以及“每段仅首次出现时应用”和“悬停显示名称，保留原词”两个开关

默认开启悬停名称，关闭首次限制；原文根据正文语言选择英文或中英名称，其他栏目默认混合全称。替换只影响显示，原始文字、代码、网址、公式和笔记保持原样；PDF 页面像素不会被改字
