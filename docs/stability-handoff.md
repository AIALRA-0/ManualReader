# 这份稳定交接版改了什么

本地候选版以 v0.4.2 为基础；它保留原文、译文、讲解、问答、术语、练习和文件标签页的现有工作流，没有迁移个人数据，也没有重新生成旧内容。部署前先备份数据目录，按部署说明替换程序；不要用发行包覆盖已有数据库、原件或配置。

## 连接后怎样减少重复读取

手动触发 Codex 后，先读取当前项目的 `GET /api/guide?view=bootstrap`。这个视图提供项目、授权范围、当前章节、待答数量、模型配置及客户端清单；完整写作规则仍由客户端读取，人工调查需要时可读取原来的 `GET /api/guide`。项目权限和章节手动已读规则保持不变。

客户端继续使用 `daily` 处理问答，使用 `teach` 生成当前章节；正文、术语和练习在同次写作中完成。主对话不需要重新读取整份材料、重抄正文或逐条启动写作者。主对话、客户端调度和写作者仍分别计量，不能把脚本本身没有 Token 消耗写成整个调度没有消耗。

## 怎样只补齐不足的术语

用户需要维护旧术语时，运行当前项目的命令；连接方式与其他客户端命令相同：

```sh
python reader_bridge.py --base <网站地址> --material <项目编号> terms --out <独立任务目录>
```

客户端通过 `GET /api/terms?needs_revision=1` 读取需要补齐的条目，每组最多八个、最多两组同时写作，采用当前配置的 Sol high 普通服务。它只请求不足的段落；合格段落作为上下文保留，输出结构要求相应字段为 `null`。服务器接收 `POST /api/terms` 的 `repair_only: true` 更新，并核对版本及旧文字，避免覆盖期间产生的新内容。

每组依次保存输入、输出结构、原始成稿、用量回执、拟写入字段和写回回执。用同一输出目录恢复时，先读回核对；已经完成的成稿直接复用，不重新生成；后来编辑过的内容保留，不能拿旧稿覆盖。旧编号、关联和修订历史继续保留。日常问答不需要额外运行这项维护。

术语仍为定义与直观解释两段，分别至少八十和一百个非空白字符；内容要讲清是什么、用途及机制，例子对应实际动作。新增术语不能通过遗漏写作版本绕过检查，按已有编号复用合格术语则不会触发重写。

## 怎样保留检索质量并减少重复输入

稳定的基础概念直接解释；产品、作品设定和具体规格缺少依据时，继续搜索并打开来源。纯搜索先返回简短候选；四个查询同批时保留工具要求的中等长度，打开网页、查找证据、查看图片和混合请求保留所请求的范围，不截断讲解或原文证据。

同一网站、同一项目可复用已打开并在合格成稿中引用的来源片段；缓存默认一天有效。新缓存逐页核对网址与正文，旧版缓存因分块方式可能混页而不直接使用；原缓存文件和用户内容均不删除。重复打开可能是在读不同位置，不能只按网址相同就删掉证据。

没有引入全文摘要、历史压缩、向量数据库或额外审稿模型。对相同工具文本做精确去重的试验收益低于千分之一，因此没有加入正式链路。

## 中断时怎样保存成稿与用量

传输器读取结束时没有换行的最后一条 SSE 回执；本地客户端断开后，仍接收已经开始的上游生成并保存公开正文及回执。上游本身中断且没有返回用量时，记录为不完整，不能估成零或假定已经成功。原始输出保留在任务目录，恢复前先检查已有成稿。

`term-maintenance-result.json` 分别列出本任务累计写作回执和本次新增调用；恢复任务不重复累计模型调用。缓存是输入中的一部分，推理是输出中的一部分，不能重复相加；费用只按明确的计价来源折算，没有实际账单时保留为空。主 Codex 对话的读取、启动、等待和汇报需要在最终汇报结束后另行结算。

## 本地实际验证了哪些内容

- 访谈与 EXAM2 的隔离副本共十八个桌面、手机竖屏及横屏场景，实际点击问答、追问和原文联动，并检查章首问题自动保存
- 同两份大项目的六个尺寸场景，实际打开与关闭两段式术语，核对显示与页面宽度
- 二十四个真实术语的新旧对照，并为需要检索的两组增加来源缓存复用测试；所有写作均为 Sol high 普通服务，未增加审稿模型
- 本地 HTTP 模拟连接验证末行回执、客户端断开和上游异常；同一真实长日志读回的八十五次调用用量完全相同

上述交互测试仅修改隔离副本；原编号、笔记、练习作答和手动已读进度作为不变量核对。测试结果不代表已经部署官网。
