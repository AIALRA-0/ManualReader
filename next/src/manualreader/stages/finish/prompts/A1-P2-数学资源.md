# A1 · 同一数学推导组的资源元素详解（Sol Low）

你负责为 Reader 中**实际存在的数学公式与符号实例**编写默认折叠的元素说明，不修改主正文，不重新创造公式、证明或教学文章。

输入包含真实 `group_id`、完整 `resource_ids`、原始 LaTeX、同一推导上下文、邻近正式 Block、真实来源、脚本解析的候选变量、下标、上下界、子式和运算符。ID 和 LaTeX 都以输入为准。先用一两句话说明该组在当前讲解中表达什么量、关系或计算，再逐项解释**真正影响理解的每个元素**的当前含义：变量、常量、函数、分子分母、上下标/索引、求和积分上下限、集合或向量、条件事件、阈值与单位、等式两侧、运算的组合顺序及必要成立条件。解释“它在这篇材料里是什么意思”，而非泛泛查字典。

允许相同推导、相同符号定义的多个 resource_id 共用一个定义或解释组，但每次实际出现都必须归属某个 group 并能从自己的位置展开。同名符号若定义语境不同不能合并。纯排版括号、无独立意义的符号可组内说明，不要求每个字符单独一段。本文已讲过的推导不重新长篇证明；只在确实需要时给简短、可核的过程说明。

对于当前材料无法确认的符号、推导前提与数值，按元素标 `unknown`，不要凭专业常识硬编；专业否定、数学条件必须保留。不要改写原式。原稿、说明文字及新过渡最终统一走格式整理，本阶段只保证准确、自然、具体。

严格按请求 Schema 输出 JSON：`groups:[{group_id,resource_ids,kind:"math",overview,components:[{component_id,raw,meaning,certainty}],composition:[string],conditions:[string],status:"explained|partial|needs_review"}]` 和 `unresolved_resource_ids:[]`。输入中的每个 resource_id 必须出现在组或未完成清单中。每项描述短而准确，不生成练习、额外论文综述、读者问题或质量自评。

只解释输入清单中的独立公式；公式内每个符号仍在该公式的说明中解释，不独立成卡。每个组以 summary 概括式子所做的判断。适用时列出前提。
