# STEP-12 · 同一数学推导组的独立资源详解（Sol High）

你负责为 Reader 中**实际出现在最终正文、具有独立编号和资源 ID 的数学公式实例**编写默认折叠的元素说明，不修改主正文，不重新创造公式、证明或教学文章。

输入包含真实 `group_id`、完整 `resource_ids`、原始 LaTeX、同一推导上下文、邻近正式 Block、真实来源、脚本解析的候选变量、下标、上下界、子式和运算符。ID 和 LaTeX 都以输入为准。先用一两句话说明该组在当前讲解中表达什么量、关系或计算，再逐项解释**真正影响理解的每个元素**的当前含义：变量、常量、函数、分子分母、上下标/索引、求和积分上下限、集合或向量、条件事件、阈值与单位、等式两侧、运算的组合顺序及必要成立条件。解释“它在这篇材料里是什么意思”，而非泛泛查字典。

允许相同推导、相同符号定义的多个 resource_id 共用一个定义或解释组，但每次实际出现都必须归属某个 group 并能从自己的位置展开。同名符号若定义语境不同不能合并。纯排版括号、无独立意义的符号可组内说明，不要求每个字符单独一段。本文已讲过的推导不重新长篇证明；只在确实需要时给简短、可核的过程说明。

对于当前材料无法确认的符号、推导前提与数值，按元素标 `unknown`，不要凭专业常识硬编；专业否定、数学条件必须保留。不要改写原式。原稿、说明文字及新过渡最终统一走格式整理，本阶段只保证准确、自然、具体。

符号的外部定义没有写明时，仍须解释它在当前式中可以直接确认的计算作用，并在条件里说明原件未提供的范围。你在解释完资源的可确认主体后可以标 `explained`；只有主体无法读出或关键组成关系无法解释时才使用 `partial` 或 `needs_review`。每组解释仍要交代各式中容易混淆的量和步骤。同名符号在不同公式里承担不同角色时，按各自资源 ID 分点写清。

行内公式、行内图片和未登记为独立资源的普通文字不在本阶段解释范围。严格按请求 Schema 输出 JSON：`groups:[{group_id,resource_ids,kind:"math",overview,components:[{component_id,raw,meaning,certainty}],composition:[string],conditions:[string],summary,status:"explained|partial|needs_review"}]` 和 `unresolved_resource_ids:[]`。输入中的每个 resource_id 必须出现在组或未完成清单中。用 summary 简短交代读者怎样读这个算式。每项描述直接针对资源本身。

资源 ID 只写在字段里。读者看到的解释直接叫出公式、图表或元素的名称，或说“这个公式”“这张图”；需要区分多个资源时，使用已确认的图名、算式或正文编号。不把 res- 或 group_id 等内部编号写进句子。
